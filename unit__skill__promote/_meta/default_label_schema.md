# Default Label Schema

The baseline vocabulary for labeling skills. Two layers:

- **`default_label_schema.md`** (this file) - the shared axes and their baseline values. One copy for the whole library - held by `unit__skill__promote`.
- **`skill_label_taxonomy.md`** - per-folder extensions only. Never repeats a value from this file.

A reader merges the two: default ∪ local.

Labels live on the first line of `usage.md`, nowhere else - generated by
`unit__skill__promote`:

```markdown
> labels: <Scope>, <Level>, <Subject>[, <Subject>]
```

A skill with no `usage.md` has no labels yet.

The vocabularies below are the current set, not a frozen one. Add a value when a skill
genuinely needs it - to this file if it is general, to a `skill_label_taxonomy.md` if it
is folder-local. One thing may not change: **the three vocabularies stay disjoint.**
That is what lets a reader classify a token without knowing the schema's contents.

## Scope - exactly one

How wide the skill applies.

| Label     | Means                                                        |
|-----------|--------------------------------------------------------------|
| `Harness` | Shapes how Claude works across many tasks                    |
| `Task`    | Does one specific job when asked. Disposable, self-contained |
| `Project` | Defines or operates this library itself                      |

## Level - exactly one

How much the skill bundles.

| Label  | Means                                        |
|--------|----------------------------------------------|
| `Unit` | one unit, no dependencies                    |
| `Flow` | combines multiple units into a task workflow |

## Subject - zero to three

What the skill is about. Shared vocabulary across every taxonomy file.

| Label      | Means                            |
|------------|----------------------------------|
| `Code`     | Source code Claude writes        |
| `Writing`  | Prose Claude writes for a human  |
| `Diagram`  | Visual output                    |
| `Workflow` | Repeatable workflow structure    |
| `Skill`    | Skills and rule files themselves |

Because the vocabularies are disjoint, a token identifies its own axis - parsing does
not depend on position. Position is fixed for readability only.

## Rules

- 2-5 labels: exactly one Scope, exactly one Level, zero to three Subjects.
- Reuse before inventing - check this file, then the local taxonomy.
- Extensions go in `skill_label_taxonomy.md`; never repeat a default there.
- Drop a label that fits one skill when that skill's name already says it.
- Drop `Workflow` when the Level is already `Flow` - it repeats the same fact.
- A Subject label on every skill classifies nothing - split it or drop it.
